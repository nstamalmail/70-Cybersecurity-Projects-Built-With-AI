# ARP Scanner — Live-Host Discovery Tool
## Detailed Architecture (v1.0)

**Product:** GUI-based network ARP scanner / live-host discovery tool for Windows
**Language:** Python 3.10+ (tested on 3.12)
**GUI:** Tkinter (stdlib) — zero external GUI dependencies
**Scan engine:** Windows `SendARP` API via `ctypes` (hybrid strategy)
**Packaging:** PyInstaller → single portable `.exe`

---

## 1. Goals & Constraints

| ID | Goal |
|----|------|
| G1 | Discover live hosts on the local IPv4 subnet via ARP resolution |
| G2 | Show vendor (OUI) identification per MAC address |
| G3 | Export results to CSV and JSON |
| G4 | Run as a **portable exe** with **no installation, no Npcap, no admin rights** |
| G5 | Never block the UI thread — all I/O is asynchronous |
| G6 | Reusable headless core (CLI usable later without the GUI) |

**Non-goals (v1):** OS fingerprinting, port scanning, IPv6, spoofing/mitM, Linux/macOS `SendARP` (API is Windows-only).

### Why hybrid `SendARP` instead of Scapy?

| Criterion | Scapy raw ARP | Ping+ARP cache | **SendARP (chosen)** |
|---|---|---|---|
| Needs Npcap / WinPcap | Yes | No | **No** |
| Needs admin rights | Yes | No | **No** |
| Sees hosts w/ host firewall | Yes (crafts ARP) | No | **Yes*** |
| Single-file exe size | ~25 MB + Npcap DLLs | ~12 MB | **~12 MB** |
| Windows-only | No | No | **Yes (accepted)** |

\* `SendARP` triggers an actual ARP request through the Windows TCP/IP stack; a host responds at the L2 layer regardless of its host-firewall's ICMP policy. A host that blocks *all* ARP replies still cannot function on an IP network, so coverage is effectively full for reachable hosts.

```
│  │              │   (threadsafe)│  │ oui.py      (OUI db)    │ │ │
│  │  - toolbar   │               │  │ engine.py   (SendARP)   │ │ │
│  │  - ttk.Treeview           │  │ exporter.py (CSV/JSON)  │ │ │
│  │  - statusbar │               │  └─────────────────────────┘ │ │
│  └──────────────┘               └─────────────────────────────┘ │

│         │                                   │ ctypes             │
│         ▼                                   ▼                    │

│  (app/export/)                       GetAdaptersInfo / SendARP   │
└─────────────────────────────────────────────────────────────────┘
```

**Layer rules (enforced by import discipline):**
1. `core/` never imports from `ui/` — the core is headless-testable.
2. `ui/` talks to `core` only via public functions returning dataclasses, or by submitting a *scan job* and receiving events from a `queue.Queue`.
3. Windows API calls exist in exactly one place: `core/interface.py` + `core/engine.py`.
4. No global mutable state; a `ScanConfig` dataclass is the single source of truth for a run.

## 4. Core Layer — Detailed Design

### 4.1 `core/models.py` — data model

```python
@dataclass(frozen=True)  ScanConfig
    cidr: str                    # e.g. "192.168.1.0/24"
    timeout: float = 2.0         # per-host ARP timeout (informational for SendARP)
    max_workers: int = 128       # thread-pool width
    ports: tuple = ()            # reserved (future use)

@dataclass(frozen=True)  Host
    ip: str                      # dotted quad
    mac: str                     # canonical "AA:BB:CC:DD:EE:FF"
    vendor: str                  # OUI vendor string ("" if unknown)
    hostname: str                # reverse-DNS lookup result ("" if failed)

@dataclass(frozen=True)  ScanResult
    cidr: str
    started: datetime
    finished: datetime
    hosts: list[Host]            # sorted by IP

@dataclass            ScanEvent          # UI-facing progress message
    kind: str                    # "start" | "progress" | "host" | "done" | "error"
    value: object                # depends on kind
```

Sorting/serialization helpers live on the dataclasses: `ScanResult.to_json_dict()`, `Host.to_row()`.

### 4.2 `core/interface.py` — NIC discovery (ctypes)

Windows API used: **`GetAdaptersInfo`** from `iphlpapi.dll`.

- `IP_ADAPTER_INFO` struct is declared with correct paddings (string 260 chars, MAX_ADAPTER_ADDRESS_LENGTH=8) — see memory.md for the alignment gotcha.
- Function `list_interfaces() -> list[dict]` returns, per adapter:
  `{ name, description, ip, netmask, cidr, gateway, mac }`
- Netmask→prefix conversion computed locally (`_netmask_to_prefix`) — no socket.io-style libs.
- Adapter selection rule for default CIDR: **first adapter that has a gateway and a valid /8../32 mask**, excluding loopback/APIPA (`169.254.0.0/16`).
- This module is *import-guarded*: on non-Windows it raises `NotImplementedError("Windows-only")` so tests on CI can skip.

### 4.3 `core/engine.py` — the scanner

**Windows API used: `SendARP`** from `iphlpapi.dll`.

```c
DWORD SendARP(IPAddr DestIP, IPAddr SrcIP, PULONG MacAddr, PULONG PhysAddrLen);
```

ctypes binding:

```python
_arp = ctypes.WinDLL("iphlpapi", use_last_error=True)
_sendarp = _arp.SendARP
_sendarp.argtypes  = [ctypes.c_uint32, ctypes.c_uint32,
                      ctypes.POINTER(ctypes.c_uint8*6), ctypes.POINTER(ctypes.c_uint32)]
_sendarp.restype   = ctypes.c_uint32
```

Return-code mapping (`DWORD`): `0` = success; `31` `ERROR_GEN_FAILURE`, `67` `ERROR_BAD_NET_NAME`, `121` `ERROR_SEM_TIMEOUT`, `1231` `ERROR_NETWORK_UNREACHABLE` → "no reply".

**Algorithm (`scan(cidr, config, event_cb)`):**

1. Parse CIDR with `ipaddress.ip_network(strict=False)` → host list (excluding network & broadcast for `/N<31`).
2. Optional self-IP excluded from targets (known responder).
3. `concurrent.futures.ThreadPoolExecutor(max_workers=config.max_workers)`.
4. Each worker calls `_arp_probe(ip)` → resolves ARP by invoking `SendARP`; on success converts the 6-byte buffer to canonical MAC `AA:BB:CC:DD:EE:FF`.
5. Each hit emits `ScanEvent("host", Host(...))` immediately (streaming UI), then OUI + reverse-DNS resolution.
6. Main thread aggregates; emits `progress` every N probes and `done` with `ScanResult`.
7. Cancellation: a `threading.Event` flag checked by workers → cooperative cancel within one probe's latency.

**Concurrency notes:** 128 workers default. Windows sends the ARP request synchronously per call, so the pool width directly bounds scan wall-time. A /24 sweeps in ≲3–5 s. Rate is polite by design — one ARP request per IP, one pass, no retry storm.

### 4.4 `core/oui.py` — vendor identification

- Embedded dictionary `OUI_DB: dict[str(prefix+"-"), vendor]` covering ~300 top vendor prefixes (Apple, Dell, HP, Cisco, Samsung, Huawei, Intel, Realtek, ASUSTek, Xiaomi, Raspberry Pi Trading, Microsoft, VMware, Ubiquiti, MikroTik, TP-Link, LG, Sony, Gigabyte, MSI, Quanta, Hon Hai, Elitegroup, Wistron, Compal, Inventec, Aruba, Netgear, D-Link, Synology, QNAP, Supermicro, IBM, Lenovo, Oracle/Sun, Fujitsu, Toshiba, NEC, Brother, Canon, Epson, Xerox, Roku, Amazon, Google, Nvidia, AMD, Qualcomm, Broadcom, Marvell, MediaTek, azure_wave, Murata, HonHai, Lite-On, Foxconn, Pegatron, Elite, Actiontec, …).
- `lookup(mac) -> str`: normalizes MAC, reads the first 3 octets, exact match on the prefix.
- Optionally, if a larger OUI dataset is dropped next to the exe as `oui.txt` (IEEE format), it is loaded and merged at startup — but the embedded DB ships by default so the exe stays self-contained.

### 4.5 `core/exporter.py` — exports

- `export_csv(result, path)`: columns `ip, mac, vendor, hostname`. Plain `csv` module, UTF-8 with BOM so Excel opens it cleanly.
- `export_json(result, path)`: full `ScanResult.to_json_dict()` including scan metadata (`cidr`, `started`, `finished`, `duration_s`, `host_count`).
- Pure functions, no filesystem paths invented inside — caller passes the full destination path.

### 5.2 Threading & the UI event loop

**Rule: the Tk mainloop thread never touches the network.**

```
UI thread                          Scanner thread
─────────                          ──────────────
btn Scan → thread.start(scan_job)
   │                                    │ engine.scan(...)
   │  ◄── queue.Queue ──────────────────│  ScanEvent("progress", n)
   │  ui.after(100ms) drain queue       │  ScanEvent("host", Host)
   │     update Treeview / statusbar    │  ScanEvent("done", ScanResult)
   ▼                                    ▼
```

- Single `queue.Queue` bridges scanner → UI. The UI polls with `root.after(100, drain)` — the canonical Tk-safe pattern.
- `Scan` button is disabled while a job is running; `Stop` sets the cooperative cancel flag.
- On `done`: results re-sorted by IP, summary line updated, exports enabled.
- On `error`: `messagebox.showerror`, statusbar reset.

## 6. Packaging — Portable `exe` (PyInstaller)

**Command (wrapped by `build.py`):**

```
pyinstaller ARPScanner.spec --clean --noconfirm
```

**Spec highlights:**

- `onefile=True` → single `dist/ARPScanner.exe`, no install step (G4).
- `console=False` → GUI app; no console window flashes.
- `name="ARPScanner"`.
- `excludes`: `unittest`, `pydoc_data`, `distutils` (size trim).
- Runtime stdlib-only → **no hidden-import problems**, no bundling of `scapy`/`np.cap` DLLs, no Npcap runtime requirement.
- Target artifact ≈ 10–13 MB; start time ≈ 1–2 s (onefile self-extract).

**Build flow (`build.py`):**
1. Ensure venv exists (`.venv`), else create it.
2. `pip install -r requirements.txt` (only `pyinstaller`).
3. Regenerate `ARPScanner.spec` from code defaults (idempotent).
4. Run PyInstaller; verify `dist/ARPScanner.exe` exists; print size.

**Distribution:** copy the single exe anywhere (USB, `\\server\share`, email) — runs as user, requests no elevation, writes nothing outside its chosen export paths.

## 7. Data Flow (end-to-end scan)

```
User clicks Scan
  → UI reads adapter/CIDR widgets → ScanConfig(cidr=…)
  → thread: engine.scan(cfg)
      → interface already resolved IPs → ipaddress parses host list
      → ThreadPool(128) × SendARP(ip)
      → replies → Host(ip, mac, vendor=oui.lookup(mac), hostname=rdns(ip))
      → ScanEvent stream → queue → UI drains → Treeview rows appear live
  → done → ScanResult(…, hosts sorted) → statusbar summary
  → Save CSV/JSON → exporter → user-chosen path
```

## 8. Error Handling Matrix

| Condition | Detection | Response |
|---|---|---|
| Invalid CIDR typed | `ipaddress` raises | inline red status message, no scan started |
| No adapter w/ gateway | `list_interfaces()` empty | dialog: "No suitable network adapter found" |
| `SendARP` failure codes | nonzero DWORD | silently treat as offline host (normal case) |
| Unreachable network | `ERROR_NETWORK_UNREACHABLE` | statusbar warning after sweep |
| Export path not writable | `OSError` | `messagebox.showerror` |
| GUI crash mid-scan | thread keeps queue | daemon thread dies with main process |

## 10. Security Considerations (senior-dev review)

1. **Authorized use only.** ARP sweeps are a classic internal-recon technique. The tool is for inventory of *your own* network; the README and About dialog state this explicitly. A `--cli` banner prints a usage notice.
2. **No admin/Npcap dependency** removes a whole class of supply-chain / driver risk for end users.
3. **No network writes** beyond normal ARP requests; no packet crafting; no spoofing capability shipped.
4. **Results files** (CSV/JSON) can reveal network topology → encourage secure storage; exports never auto-write to disk without a user-visible save dialog.
5. **Input surface is tiny:** one CIDR string validated by `ipaddress` before any use; no eval/exec, no dynamic imports, no shell-outs.
6. **ctypes surface:** only two well-documented `iphlpapi` functions; buffer sizes fixed (6-byte MAC), no pointer arithmetic beyond struct field access.
