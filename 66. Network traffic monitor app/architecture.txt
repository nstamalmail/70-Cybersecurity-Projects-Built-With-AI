# Architecture: Network Traffic Monitor for Android

**Codename:** `NetScope`
**Document Version:** 1.0.0
**Target Platform:** Android 8.0+ (API 26+) — full per-app attribution on Android 10+ (API 29+)
**Build Target:** `.apk` via Buildozer / python-for-android
**Author Role:** Senior Security Developer
**Classification:** Internal Engineering Spec

---

## 1. Executive Summary

NetScope is an **on-device, privacy-preserving** network traffic monitor that reports **per-application bandwidth usage** (upload/download, foreground/background, mobile/Wi-Fi) in real time and historically. It performs **all analysis locally**, ships with **no analytics**, and requires the elevated `android.permission.READ_NETWORK_USAGE_HISTORY` (system-restricted) or falls back to **VPNService-based local capture** for unprivileged builds.

The GUI and orchestration are written in **Python 3.11** using **KivyMD**, packaged for Android via **Buildozer**. Kernel/OS telemetry is bridged through **pyjnius** to `NetworkStatsManager`, `ConnectivityManager`, and a Python-controlled **VpnService** (for per-flow capture when stats permission is unavailable).

> **Reality check (senior-dev honesty):** True *per-app* byte accounting on Android without root is only available via `NetworkStatsManager` (requires `PACKAGE_USAGE_STATS` + on some OEMs `READ_NETWORK_USAGE_HISTORY`). If those are denied, the app degrades to a **userspace VPN tunnel** that attributes flows to UIDs via `ConnectivityManager.getConnectionOwnerUid()`. Both paths are specified below.

## 2. Design Goals & Threat Model

### 2.1 Goals
| ID | Goal |
|----|------|
| G1 | Accurate per-app byte counters (rx/tx), split by network type & foreground/background. |
| G2 | No traffic content inspection — metadata only (5-tuple + byte counts). |
| G3 | Zero data egress: no telemetry, no cloud, no third-party SDKs. |
| G4 | No persistent packet payloads; flow records only, with configurable retention. |
| G5 | Minimal permissions; graceful degradation when privileged APIs are denied. |
| G6 | Foreground service with persistent notification (Android 8+ requirement). |
| G7 | Auditable, reproducible build (SBOM, pinned deps). |

### 2.2 Threat Model (STRIDE-lite)

**In scope:**
- Malicious app on same device reading our local DB (mitigated: app-private storage + SQLCipher optional).
- Network attacker (N/A — we send nothing).
- Adversarial app that *is* the traffic being measured (we never trust it; we read OS counters).
- Shoulder surfing of dashboards (FLAG_SECURE on sensitive screens).
- Abuse of the VpnService to intercept other apps (mitigated: we never route packets to a remote endpoint; tun loop reads counters only).
- Forensic extraction of flow history (mitigated: encrypted DB, retention limits, wipe-on-uninstall).

**Out of scope:**
- Rooted device with live kernel hooking.
- Compromised OS / malicious firmware.
- ISP-level correlation (we don't claim to defeat it).
- Content-level DPI (we explicitly do **not** do this).

## 5. Data Collection Design

NetScope supports **two collection backends** chosen automatically at runtime:

### 5.1 Backend A — `NetworkStatsManager` (preferred)

**Permissions:**
- `android.permission.PACKAGE_USAGE_STATS` (via Settings → Special access, user-granted)
- `android.permission.READ_NETWORK_USAGE_HISTORY` (signature-level on most ROMs; only granted to system/privileged apps)
- `ACCESS_NETWORK_STATE`, `ACCESS_WIFI_STATE`

**API surface (via pyjnius):**
```
NetworkStatsManager.queryDetailsForUid(
    networkType, subscriberId, startTime, endTime, uid)
NetworkStatsManager.querySummaryForDevice(...)
NetworkStats.Bucket.getRxBytes()/getTxBytes()/getStartTimeStamp()/getEndTimeStamp()
```

**Granularity:** per-UID, per-networkType (WIFI/MOBILE), foreground vs background not always separable — combined via periodic diffing.

**Polling cadence:** adaptive — 5 s on screen, 30 s backgrounded, 5 min doze.

### 5.2 Backend B — `VpnService` userspace tap (fallback)

Used when stats permission is denied. Design principle: **we are a sinkhole counter, not a tunnel**.

- Establish `Builder().addAddress("10.8.0.1", 32).addRoute("0.0.0.0", 0).establish()`.
- Read raw IP packets from the tun fd; parse IPv4/IPv6 + TCP/UDP headers only.
- Attribute each flow to a UID via `ConnectivityManager.getConnectionOwnerUid(proto, local, remote)`.
- Increment counters, then **forward packets unchanged** to the real network using a protected socket (`VpnService.protect()`), preserving user connectivity.
- **No payload is logged**, no reassembly, no DPI. Only `(uid, proto, saddr, sport, daddr, dport, bytes, ts)` tuples in RAM, flushed as aggregates.

**Hard guarantees:**
- Flow records flushed to DB every 10 s.
- Raw packets dropped immediately after counting (no buffering beyond one MTU).
- No DNS inspection (the resolver is left untouched).

### 5.3 Backend selection matrix

| Condition | Backend |
|-----------|---------|
| `PACKAGE_USAGE_STATS` granted | A |
| VPN consent granted, stats denied | B |
| Both denied | UI-only, prompts user |
| Rooted (future) | Optional A + `/proc/net/xt_qtaguid` cross-check |

## 6. Data Model

### 6.1 Flow sample (hot path — RAM ring buffer)
```
FlowSample {
  ts_ms        : int64
  uid          : int32
  iface        : enum{WIFI, MOBILE, VPN, OTHER}
  direction    : enum{RX, TX}
  bytes        : int64
  fg           : bool       # app foreground at sample time
}
```

### 6.2 SQLite schema (SQLCipher-encrypted)

```sql
CREATE TABLE flows (
  id       INTEGER PRIMARY KEY,
  ts_ms    INTEGER NOT NULL,
  uid      INTEGER NOT NULL,
  iface    TEXT    NOT NULL,
  dir      TEXT    NOT NULL,
  bytes    INTEGER NOT NULL,
  fg       INTEGER NOT NULL
);
CREATE INDEX idx_flows_ts  ON flows(ts_ms);
CREATE INDEX idx_flows_uid ON flows(uid, ts_ms);

CREATE TABLE rollups_hourly (
  hour_ms  INTEGER NOT NULL,
  uid      INTEGER NOT NULL,
  iface    TEXT    NOT NULL,
  rx       INTEGER NOT NULL,
  tx       INTEGER NOT NULL,
  PRIMARY KEY (hour_ms, uid, iface)
);

CREATE TABLE rollups_daily (
  day_ms   INTEGER NOT NULL,
  uid      INTEGER NOT NULL,
  iface    TEXT    NOT NULL,
  rx       INTEGER NOT NULL,
  tx       INTEGER NOT NULL,
  PRIMARY KEY (day_ms, uid, iface)
);

CREATE TABLE apps (
  uid          INTEGER PRIMARY KEY,
  package_name TEXT,
  label        TEXT,
  icon_blob    BLOB,       -- cached, not sensitive
  first_seen   INTEGER,
  last_seen    INTEGER
);

CREATE TABLE prefs (
  key   TEXT PRIMARY KEY,
  value TEXT
);
```

**Retention policy (default):**
- Raw flows: 24 h
- Hourly rollups: 30 d
- Daily rollups: 365 d
- Vacuum + `PRAGMA secure_delete=ON`.

### 6.3 Encryption model
- DB key = random 32 B, generated on first run.
- Wrapped with AES-GCM using a Keystore-backed key (`setUserAuthenticationRequired(false)` — the app must run headless in a service; biometric gate is optional for the DB *viewing* screen only).
- Wrapped key stored in app-private `files/dbkey.wrap`.
- Optional "Paranoid mode": require biometric to open dashboard; service continues counting using an in-memory cached key unwrapped at boot.

## 8. Runtime Lifecycle

```
App start
  │
  ├─► Check permissions
  │     ├─ PACKAGE_USAGE_STATS granted → Backend A
  │     └─ else prompt VPN consent    → Backend B
  │
  ├─► Start ForegroundService(MetricsService)
  │     ├─ open encrypted DB
  │     ├─ spawn collector thread (Python)
  │     └─ register ConnectivityManager.NetworkCallback
  │
  ├─► Launch UI (KivyMD)
  │     └─ bind to aggregator via observer pattern
  │
  └─► onDestroy → flush → zeroize keys → close DB
```

**Threading model:**
- 1 collector thread (JNI calls are blocking; never on UI thread).
- 1 aggregator thread (consumes ring buffer → DB batches).
- UI runs on Kivy's main loop; reads from in-RAM aggregator snapshot (no DB hits on UI thread).

```xml
<uses-permission android:name="android.permission.INTERNET"/>            <!-- required for VPN protect socket; NOT used for telemetry -->

<uses-permission android:name="android.permission.ACCESS_WIFI_STATE"/>
<uses-permission android:name="android.permission.PACKAGE_USAGE_STATS"
                 tools:ignore="ProtectedPermissions"/>
<uses-permission android:name="android.permission.READ_NETWORK_USAGE_HISTORY"
                 tools:ignore="ProtectedPermissions"/>
<uses-permission android:name="android.permission.FOREGROUND_SERVICE"/>
<uses-permission android:name="android.permission.POST_NOTIFICATIONS"/>
<uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED"/>

<application
    android:allowBackup="false"
    android:fullBackupContent="false"
    android:dataExtractionRules="@xml/no_backup"
    android:usesCleartextTraffic="false"
    android:networkSecurityConfig="@xml/nsc_strict">
    <service android:name=".NetScopeVpnService"
             android:permission="android.permission.BIND_VPN_SERVICE"
             android:exported="false">
        <intent-filter>
            <action android:name="android.net.VpnService"/>
        </intent-filter>
    </service>
</application>
```

> **Justification for `INTERNET`**: needed solely to open protected sockets for packet forwarding in Backend B and to read `NetworkStatsManager` (some OEMs require it). No outbound connections to any server are initiated by NetScope. This is documented in `PRIVACY.md` and enforced by a CI grep gate against `socket.connect(` in non-whitelisted modules.

## 14. Performance Budget

| Metric | Target |
|--------|--------|
| CPU (screen on, 5 s poll) | ≤ 3 % |
| CPU (background, 30 s poll) | ≤ 0.5 % |
| RAM (service + UI) | ≤ 60 MB |
| DB write batch | every 10 s or 500 rows |
| Cold start to first chart | ≤ 1.5 s |
| Battery (24 h, moderate) | ≤ 2 %/day additional |

Backend B (VPN) is heavier: **≤ 8 % CPU** on a mid-tier device at 100 Mbps. Documented in the UI when the fallback is active.

## 15. Known Limitations & Residual Risk

1. **`READ_NETWORK_USAGE_HISTORY` is effectively system-only** on modern Android. Most users will land in Backend B (VPN). This is disclosed prominently.
2. **VPN mode adds a hop** in the packet path; latency impact measured ≤ 1 ms locally but non-zero.
3. **`getConnectionOwnerUid` is best-effort** — some flows may be attributed to `uid=1000` (system) or unresolved during races. Documented and surfaced as an "Unknown" bucket.
4. **Foreground/background split** is imprecise under Backend A (sampled via `ActivityManager` polling); ± 10 % attribution error possible.
5. **Doze mode** throttles polling; counters reconcile on next wake via `NetworkStatsManager` deltas.
6. **Root-only** features (`xt_qtaguid`, `nethogs`-style) intentionally excluded from v1.0.
7. **Python overhead** in the VPN fast path caps throughput; ≥ 500 Mbps links may see drops. Mitigation: kernel-side BPF is out of scope for a Python build; documented.
