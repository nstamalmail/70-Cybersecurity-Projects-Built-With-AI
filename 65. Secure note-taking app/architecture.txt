# Architecture: Secure Note-Taking App for Android

**Codename:** `SentinelNotes`
**Document Version:** 1.0.0
**Target Platform:** Android 8.0+ (API 26+)
**Build Target:** `.apk` via Buildozer / python-for-android
**Author Role:** Senior Security Developer
**Classification:** Internal Engineering Spec

---

## 1. Executive Summary

SentinelNotes is a **zero-knowledge, local-only** note-taking application for Android. All note content is encrypted at rest using **AES-256-GCM** with keys derived from a user passphrase and/or biometric-gated keystore material. The app performs **no network I/O**, contains **no telemetry**, and stores no plaintext on disk at any time.

The GUI and application logic are written in **Python 3.11**, packaged for Android using **KivyMD** + **Buildozer** (python-for-android). Biometric and Android Keystore access are bridged through **pyjnius**.

## 2. Design Goals & Threat Model

### 2.1 Security Goals
| ID | Goal |
|----|------|
| G1 | Confidentiality of note content at rest (device theft, forensic imaging). |
| G2 | Integrity & authenticity of ciphertext (tamper detection). |
| G3 | Authentication: passphrase (knowledge) + biometric (inherence). |
| G4 | No plaintext, keys, or IVs written to disk, swap, or logs. |
| G5 | Screenshot / recents-thumbnail protection. |
| G6 | Auto-lock on inactivity, background, or screen-off. |
| G7 | Resistance to offline brute-force (Argon2id, high cost params). |

### 2.2 Threat Model (STRIDE-lite)
**In scope:**
- Lost/stolen device, unlocked screen.
- Malicious app with `READ_EXTERNAL_STORAGE` (mitigated: app-private dir).
- Forensic imaging / ADB backup (mitigated: `allowBackup=false`).
- Shoulder surfing, screenshots, recents preview.
- Cold-boot key recovery (mitigated: keys only in RAM, mlock where possible).

**Out of scope:**
- Rooted device with live kernel instrumentation.
- Compromised OS / malicious firmware.
- Physical coercion (duress passphrase is a *future* feature).
- Hardware side-channel attacks.

## 4. Technology Stack

| Layer | Technology | Rationale |
|-------|-----------|-----------|
| Language | Python 3.11 | Mandated. |
| GUI | **KivyMD** (Kivy 2.3+) | Material Design on Android; mature p4a support. |
| Packaging | **Buildozer 1.5+** | Produces `.apk` / `.aab` from Python. |
| Crypto | **pyca/cryptography** (OpenSSL backend) | Audited, constant-time primitives. |
| KDF | **Argon2id** (`argon2-cffi`) | Memory-hard, side-channel resistant. |
| AEAD | **AES-256-GCM** | HW-accelerated on ARMv8 (AES-NI equivalents). |
| DB | **SQLCipher** (via `sqlcipher3`) *or* file-per-note encrypted blobs | Field-level vs whole-DB encryption. |
| Android bridge | **pyjnius** | Access `BiometricPrompt`, `KeyStore`, `WindowManager`. |
| Build | Buildozer + python-for-android (NDK r25c) | Native crypto + JNI. |

> **Note on SQLCipher vs file blobs:** Primary design uses **file-per-note encrypted blobs** (simpler key model, easier integrity). SQLCipher is a *fallback* if list/search performance degrades.

## 5. Cryptographic Design (Detailed)

### 5.1 Key Hierarchy

```
                 User Passphrase
                        │
                        │  Argon2id(salt=16B, t=4, m=256MiB, p=4)
                        ▼
              ┌─────────────────────┐
              │   Master Key (MK)   │  32 bytes, RAM-only
              │   (never stored)    │
              └─────────┬───────────┘
                        │ HKDF-SHA256 (info="sentinelnotes-v1")
        ┌───────────────┼───────────────┬────────────────┐
        ▼               ▼               ▼                ▼
   ┌─────────┐   ┌────────────┐  ┌────────────┐  ┌────────────┐
   │ DEK_note│   │ IndexKey   │  │ HMAC-Index │  │ VaultKey   │
   │ per-note│   │ (AES-GCM)  │  │ (blind idx)│  │ (settings) │
   └─────────┘   └────────────┘  └────────────┘  └────────────┘
```

- **MK** derived from passphrase with Argon2id. **Salt** stored in plaintext header (non-secret, 16 bytes).
- **Biometric unlock** does *not* replace the passphrase. Instead:
  1. On first passphrase unlock, a random 32-byte **WrapKey** is generated.
  2. WrapKey is used to AES-GCM-wrap the MK → `wrapped_mk`.
  3. `wrapped_mk` is stored in **Android Keystore** under a key with `setUserAuthenticationRequired(true)` and `BIOMETRIC_STRONG`.
  4. Biometric success → Keystore decrypts WrapKey → unwraps MK in RAM.
  - Passphrase is **never** stored, hashed, or sent to Keystore.

### 5.2 Per-Note Encryption (AEAD)

Each note is an independent record:

```
┌──────────────────────────────────────────────────────────────┐
│ HEADER (plaintext, authenticated as AAD)                     │
│  magic(4) | ver(1) | note_id(16) | created_ts(8) |           │
│  modified_ts(8) | salt(16) | argon2_params(12)               │
├──────────────────────────────────────────────────────────────┤
│ IV (12 bytes, random per-write, never reused)                │
├──────────────────────────────────────────────────────────────┤
│ CIPHERTEXT (AES-256-GCM of UTF-8 note body)                  │
├──────────────────────────────────────────────────────────────┤
│ TAG (16 bytes)                                               │
└──────────────────────────────────────────────────────────────┘
```

- **AAD** = the full header → binds metadata to ciphertext (prevents note-swap attacks).
- **IV**: 12 bytes from `os.urandom` / `secrets.token_bytes`. Per-write; a note re-encrypted on every save with a fresh IV.
- **DEK_note** = HKDF(MK, info=`"note:"+note_id`), so each note is cryptographically isolated (compromise of one DEK does not reveal others).
- **Filename on disk** = `HMAC-SHA256(IndexKey, note_id)` → prevents filename leakage of titles.

### 5.3 Blind Indexing (Search Without Decryption)

To support search without decrypting every note:
- On save, compute `tokens = tokenize(plaintext)`, then `blind_token = HMAC-SHA256(HMACIndexKey, token)`.
- Store `blind_token` list in a separate index file (encrypted with IndexKey).
- Search: HMAC the query token, match, return note_ids.
- **Trade-off**: leaks frequency of identical tokens to an attacker with filesystem access. Acceptable for a local single-user vault; documented.

### 5.4 Auto-Lock & Key Lifecycle

| Event | Action |
|-------|--------|
| App → background | Start timer (default 30s, configurable 0–300s). |
| Screen OFF (`ACTION_SCREEN_OFF`) | Lock immediately. |
| Timer expiry | `SessionManager.lock()` — zeroize MK, DEKs, plaintext buffers. |
| Process kill | OS reclaims RAM. Keys are never persisted. |
| Panic button | User-triggered instant lock + optional note wipe. |

**Zeroization:** Python lacks guaranteed memory zeroing. Mitigations:
- Store keys in `bytearray` and overwrite with `\x00` on lock.
- Prefer `cryptography.hazmat.primitives` objects that keep key material in OpenSSL `EVP` contexts (freed on `del`).
- Document that CPython GC/paging is a residual risk; recommend `mlock` via ctypes for the MK buffer where the platform permits.

### 5.5 Constant-Time Discipline
- All comparisons of tags/MACs use `hmac.compare_digest`.
- No branching on secret bytes.
- Argon2id parameters tuned to device class (see §5.6).

### 5.6 Argon2id Parameter Tuning

| Device Class | m | t | p | Target |
|--------------|---|---|---|--------|
| Low-end (2 GB RAM) | 128 MiB | 3 | 2 | ≥ 250 ms |
| Mid (4–6 GB) | 256 MiB | 4 | 4 | ≥ 400 ms |
| High (8 GB+) | 512 MiB | 4 | 4 | ≥ 600 ms |

Parameters are stored in the vault header and honored on unlock (forward-compatible migration).

## 7. Data Storage Layout

```
/data/data/com.sentinel.notes/          (app-private, mode 0700)
├── files/
│   ├── vault.hdr                # magic, ver, salt, argon2 params (PLAINTEXT)
│   ├── notes/
│   │   ├── <HMAC(note_id)>      # encrypted note blobs
│   │   └── ...
│   ├── index.enc                # AES-GCM(IndexKey) blind index
│   └── settings.enc             # AES-GCM(VaultKey) preferences
└── no_backup/                   # excluded from auto-backup
```

**AndroidManifest flags:**
- `android:allowBackup="false"`
- `android:fullBackupContent="false"`
- `android:dataExtractionRules` (API 31+) denying cloud/device transfer
- `android:excludeFromRecents="false"` but `FLAG_SECURE` hides content
- No `INTERNET` permission requested.

## 8. Authentication Flows

### 8.1 First Launch (Vault Creation)
```
User → Set Passphrase → Argon2id → MK
     → Generate WrapKey, wrap MK
     → Store WrapKey in Keystore (auth-required)
     → Prompt biometric enrollment (optional)
     → Write vault.hdr (salt + params)
     → MK held in RAM → session active
```

### 8.2 Unlock — Passphrase
```
User → Enter Passphrase → Argon2id(salt, params) → MK'
     → Decrypt a known test blob (vault canary) with MK'
     → Success → session active | Fail → backoff
```

### 8.3 Unlock — Biometric
```
User → Tap fingerprint icon → BiometricPrompt (CryptoObject)
     → Keystore decrypts WrapKey → MK unwrapped → session active
```

### 8.4 Backoff Policy
| Failures | Delay |
|----------|-------|
| 1–4 | none |
| 5 | 30 s |
| 6–9 | exponential 1→8 min |
| 10+ | optional wipe (user-configured) |

### 9.2 Build Commands
```bash

buildozer -v android release    # signed AAB for Play
```

### 9.3 CI/CD Hardening
- Reproducible builds pinned by `requirements.txt` + `p4a.branch` SHA.
- APK signed with a **hardware-backed release key** (HSM or YubiKey PIV).
- SBOM generated (`syft`) + dependency CVE scan (`grype`) in CI.
- Fails build on: new `INTERNET` permission, missing `FLAG_SECURE`, plaintext `print()` of secrets (grep gate).

## 12. Known Limitations & Residual Risk

1. **Python memory model**: keys cannot be guaranteed zeroized; GC copies may linger. Mitigated but not eliminated.
2. **Blind index leakage**: token frequency side-channel. Documented; acceptable for single-user local vault.
3. **Biometric is convenience, not root of trust**: passphrase remains the ultimate secret. If Keystore is compromised (rooted device), biometric path degrades to passphrase-only.
4. **Timing side-channels** in pure-Python tokenizer/search. Not a cryptographic boundary; noted.
5. **No duress passphrase** in v1.0 (roadmap v1.1).
6. **Kivy surface area**: large native dependency; tracked via SBOM.
